# Инструменты разработки и CI/CD

**Версия:** 1.0  
**Дата:** 2026-08-09  
**Назначение:** Описание инструментов, плагинов и практик, используемых при разработке ИИ-системы «Папай» для обеспечения качества кода, архитектурной целостности и автоматизации рутинных проверок.

---

## 1. Обзор

Разработка ведётся с активным использованием **ИИ-ассистентов** (Claude Code, Cursor, Copilot). Чтобы гарантировать, что генерируемый код соответствует строгим архитектурным требованиям, бизнес-логике и стандартам безопасности, внедряются следующие инструменты:

- **Code-Review плагин для Claude Code** – мультиагентная проверка кода перед коммитом.
- **Структурированные навыки (SKILL.md)** – контекстные инструкции для ИИ, задающие правила работы с конкретными модулями проекта.
- **(Опционально) Справочные материалы** – репозиторий `build-your-own-x` для углублённого изучения инфраструктурных компонентов.

Все эти инструменты интегрируются в пайплайн разработки и работают автоматически, не требуя ручного вмешательства.

---

## 2. Code-Review плагин для Claude Code

### 2.1 Общее описание

Официальный open-source плагин от Anthropic для Claude Code, запускающий изолированных под-агентов, которые валидируют созданный код на:

- уязвимости (инъекции, XSS, CSRF, работа с секретами);
- архитектурные ошибки (нарушение слоёв, циклические зависимости);
- соответствие стилю и стандартам кодирования (PEP8, typing, async/await);
- корректность бизнес-логики (проверка формул, граничных случаев).

Плагин автоматически подхватывается средой выполнения при вызове команд проверки или на этапе pre-commit.

### 2.2 Настройка

1. Установить плагин в рабочее окружение Claude Code (следуя официальной документации Anthropic).
2. Создать конфигурационный файл `.claude-code/config.yaml` (пример ниже).
3. Определить набор правил, специфичных для проекта «Папай».

**Пример конфигурации** (`.claude-code/config.yaml`):
```yaml
code_review:
  enabled: true
  agents:
    - security
    - architecture
    - style
    - business_logic
  rules:
    security:
      - no_hardcoded_secrets
      - no_sql_injection
      - no_xss
    architecture:
      - no_cyclic_imports
      - handlers_use_services
      - async_io
    style:
      - pep8
      - type_hints_required
    business_logic:
      - cascade_order_rag_local_cloud
      - threshold_rag_0_65
      - business_rules_engine_validation
  auto_fix: false   # агенты только находят, но не исправляют (требуется ручное одобрение)
  fail_on_warning: false  # пропускать предупреждения, останавливаться только на ошибках
2.3 Интеграция в CI/CD
Добавить шаг claude-code review --path ./app в GitHub Actions / GitLab CI перед запуском тестов.

Если плагин находит Critical ошибки – пайплайн останавливается.

Предупреждения (Warnings) логируются, но сборка не прерывается (чтобы не блокировать разработку).

2.4 Запуск вручную (для разработчика)
bash
claude-code review --path app/ --output report.html
Результат – HTML-отчёт с подсветкой проблемных мест и рекомендациями.

3. Структурированные навыки (SKILL.md)
3.1 Концепция
Вместо одного большого системного промпта, знания о проекте и правила работы разбиваются на небольшие модули – скиллы. Каждый скилл – это Markdown-файл, содержащий:

MISSION.md – цель скилла (что он должен делать).

NOTES.md – дополнительные пояснения, архитектурные решения, ссылки.

RESOURCES.md – список внешних ресурсов (документация, API, репозитории).

Папка lessons/ – примеры использования, лучшие практики.

Скиллы размещаются в директории .claude/skills/ корня проекта. ИИ-агент (Claude Code, Cursor) автоматически загружает их при работе с проектом, что гарантирует точность и исключает галлюцинации по ключевым аспектам.

3.2 Обязательные скиллы для «Папай»
Создать следующие скиллы (уже на этапе настройки проекта):

3.2.1 calculators/
MISSION.md: «Обеспечить правильную реализацию FSM-калькуляторов: расчёт модулей, кабелей, мощности, подбор комплектующих. Все формулы и коэффициенты должны строго соответствовать инженерным нормативам компании.»

NOTES.md:

Коэффициент запаса мощности – 20%.

Сечения кабелей выбираются по таблице ПУЭ.

Для модулей P2.5, P3.91, P4.81 – шаг пикселя фиксированный.

Выходные данные: мощность (кВт), номинал автоматов (А), сечение кабеля (мм?), количество БП.

RESOURCES.md: ссылки на внутренние регламенты, таблицы ПУЭ, даташиты Mean Well.

3.2.2 cascade-router/
MISSION.md: «Реализовать каскадный роутер с порядком RAG > Local > Cloud. Порог RAG_SCORE_THRESHOLD = 0.65. Облачная модель – только Anthropic Claude. Все вызовы логируются в Langfuse.»

NOTES.md:

Если RAG находит чанк с score ? 0.65 – использовать его как контекст для локальной модели.

Если локальная модель возвращает маркер [NEED_CLOUD] – эскалация в Claude.

Квоты на Cloud для пользователя – 50 запросов/день (хранятся в Redis).

Запросы с прикреплёнными файлами (PDF, видео) сразу идут в Cloud.

RESOURCES.md: документация по ChromaDB, Ollama API, Anthropic SDK.

3.2.3 database/
MISSION.md: «Спроектировать и реализовать модели PostgreSQL (SQLAlchemy 2.x async) и схемы Pydantic для всех сущностей. Обеспечить миграции через Alembic.»

NOTES.md:

Основные таблицы: users, chats, messages, projects, business_rules, reminders, activity_logs, ai_requests.

Все внешние ключи с каскадным удалением (ON DELETE CASCADE) для связанных данных.

Для messages хранить source (rag/local/cloud), tokens_used, cost.

Индексы на chat_id, user_id, created_at.

RESOURCES.md: документация SQLAlchemy, Alembic, PostgreSQL.

3.2.4 business-rules/ (опционально, на этапе 2)
MISSION.md: «Управление динамическими бизнес-правилами. Правила хранятся в БД, загружаются при старте и при добавлении/изменении. Проверка выполняется перед каждым расчётом.»

NOTES.md:

Формат правила: [условие] > [действие] (например, «ЕСЛИ шаг пикселя P10 И размер < 1м? ТО предупреждение»).

Три уровня строгости: WARNING, BLOCKING, INFO.

При нарушении BLOCKING – расчёт не выполняется.

3.2.5 testing/ (общий скилл для тестирования)
MISSION.md: «Обеспечить покрытие кода тестами (pytest) не менее 80%. Все тесты должны проходить до коммита. Использовать pytest-asyncio для асинхронных тестов.»

NOTES.md:

Структура тестов: tests/unit/ и tests/integration/.

Для интеграционных тестов использовать тестовую БД (SQLite in-memory) и замоканные внешние сервисы.

Примеры тестов для каскадного роутера, калькуляторов, FSM.

3.3 Использование скиллов в работе
При старте сессии Claude Code автоматически подгружает все скиллы из .claude/skills/.

При генерации кода для конкретного модуля агент обращается к соответствующему скиллу, что гарантирует соблюдение правил.

При возникновении неясности агент может запросить уточнение, но ответ должен быть найден в скиллах, а не в домыслах.

4. Дополнительные ресурсы (справочно)
4.1 Репозиторий build-your-own-x
Описание: Популярный open-source репозиторий codecrafters-io/build-your-own-x, содержащий пошаговые гайды по написанию собственных сложных систем (БД, Docker, веб-серверы, языки программирования).

Применимость к проекту:
Для «Папай» не является обязательным и не входит в основной пайплайн разработки. Инженеры могут использовать его как справочник для углублённого понимания внутреннего устройства инфраструктурных компонентов (например, чтобы разобраться в работе ChromaDB или Ollama при возникновении нестандартных проблем).
Рекомендуется добавить ссылку в README как дополнительный ресурс.

5. Рекомендации по внедрению в процесс разработки
Добавить в репозиторий папку .claude/skills/ с перечисленными выше скиллами (заполнить MISSION.md и NOTES.md конкретным содержанием).

Настроить Claude Code на использование плагина code-review и скиллов (указать путь в конфигурации).

Включить pre-commit хуки:

Запуск claude-code review --path ./app --fail-on-critical.

Запуск pytest с покрытием (минимальный порог 80%).

В CI/CD добавить те же проверки, чтобы предотвратить попадание некорректного кода в основную ветку.

Обновлять скиллы при изменении архитектуры или бизнес-требований – это гарантирует, что ИИ-агенты всегда работают по актуальным правилам.

6. Заключение
Использование code-review плагина и структурированных навыков позволяет:

Снизить количество ошибок при автогенерации кода, особенно в критических блоках (калькуляторы, роутер).

Ускорить онбординг новых разработчиков (скиллы служат живой документацией).

Обеспечить единообразие кода и соответствие архитектурным решениям на всём протяжении проекта.

Внедрение этих инструментов является обязательным и должно быть выполнено на этапе инициализации репозитория (до начала активной разработки).
